# AgentBreaker 🔴🤖
> Агент который читает код LLM-приложения, моделирует угрозы и ломает его точечными атаками — включая memory poisoning и indirect injection

## Что за задача и для кого

Команды активно деплоят LLM-агентов — с инструментами, доступом к данным, долгосрочной памятью, сложными цепочками вызовов. Безопасность проверяется вручную или не проверяется вообще. Существующие redteaming-инструменты (Llamator, Promptfoo) работают **вслепую**: долбят фиксированными атаками в endpoint не зная архитектуры. Они не умеют в multi-turn атаки и не тестируют память агента.

**AgentBreaker** читает GitHub-репозиторий, восстанавливает архитектуру агента — системные промпты, tools, memory-механизм, цепочки вызовов — и генерирует **точечные атаки** именно под эту конфигурацию. Включая memory poisoning и indirect injection через внешние источники данных.

Сам AgentBreaker защищён от атак которые тестирует — через двухмодельную архитектуру с privilege separation: изолированный Analyzer LLM читает опасный код репо, Orchestrator видит только структурированный JSON и никогда не касается сырых данных.

**Для кого:** ML-инженеры и команды безопасности которые деплоят LLM-агентов и хотят знать где они сломаются до того как это сделает кто-то другой. Запускается on-prem, читает репо, бьёт в staging endpoint.

## Что именно сделает PoC на демо

- Принять ссылку на публичный GitHub-репозиторий с LLM-агентом
- Прочитать код через **изолированный Analyzer LLM**: системные промпты, описания tools, memory-механизм, цепочки вызовов — вернуть структурированный JSON
- Построить модель угроз: какие классы атак релевантны именно для этой архитектуры
- Сгенерировать персонализированные атаки четырёх классов:
  - **Prompt Injection** — прямые инструкции в user message
  - **Tool Abuse** — провокация вызова tool с опасными аргументами (path traversal, SSRF)
  - **Data Leakage** — извлечение системного промпта и внутренних данных
  - **Memory Poisoning** — отравление долгосрочной памяти через multi-turn сессии
- Прогнать атаки через API тестируемого агента или мок-контур, multi-turn для memory poisoning
- Judge оценить каждый результат: утечка / нежелательный tool call / успешное отравление памяти
- Выдать отчёт: что сломалось, насколько критично, как воспроизвести
- Автоматически создать GitHub Issues с findings (с подтверждением пользователя)

## Что НЕ делает PoC (out-of-scope)

- ❌ Поддержка приватных репозиториев
- ❌ Атаки на browser-based агентов (Playwright/Selenium)
- ❌ Автоматический фикс найденных уязвимостей
- ❌ Полная trifecta цепочка (indirect injection → tool abuse → exfiltration) 
- ❌ Полное покрытие OWASP LLM Top 10
- ❌ Интеграция с Jira
- ❌ Тестирование живых продакшн-систем с реальными данными
- ❌ Regression CI/CD pipeline
